Project Overview

This project demonstrates a complete machine learning pipeline for embedded inference—training a model on a powerful GPU workstation (ai.local) and deploying it to resource-constrained hardware (Raspberry Pi, ESP32, ARM microcontrollers) via two independent paths: Python with ONNX Runtime or native C/C++ compiled code.

The workflow at a glance

Phase 1 (Training): Build and train a nonlinear neural network on ai.local (RTX 3070 VRAM) using PyTorch. Fit the model to multidimensional input data with ReLU activations.
Phase 2 (Export): Save trained weights in two formats:
• Path A: Export to ONNX format + normalization statistics for Python inference
• Path B: Extract weights into C header files + generate native C/C++ inference code
Phase 3 (Deploy): Copy files to Pi via sshpass + SCP. Compile (if needed) and run inference directly on the target device.
Phase 4 (Execute): Run predictions on hardware with latency measured in microseconds. No deep learning frameworks required on the target.

Why two paths?

Path A (Python ONNX): Flexible, portable, uses ONNX Runtime. Good for devices with Python + libonnxruntime (Linux, some microcontroller frameworks). Slightly higher overhead but easier debugging.

Path B (C/C++): Zero-framework, compiled-in weights, minimal binary footprint, near-zero inference latency (~1 µs). Ideal for constrained environments (ESP32, bare-metal ARM).

Key technical decisions

  • Normalization: Input statistics (mean/std) are saved separately and applied before inference. This improves model training and generalization.
  • History/feedback loops: Files 2 and 3 demonstrate feeding model outputs back as inputs—useful for signal reconstruction and time-series tasks.
  • Auto-deployment: File 3 uses subprocess.run with sshpass to eliminate manual SSH steps. The Pi compiles and tests automatically.
  • Weight format: Weights are stored as plain C float arrays—no dynamic allocation, no serialization overhead.

File 1: 1pytorch.py — Basic Training

This is the simplest file—a good starting point for learning PyTorch fundamentals. It trains a linear model (no hidden layers) on synthetic data.

What it does

  1. Checks if GPU is available and prints status
  2. Creates a synthetic CSV with inputs x1, x2 and output y = 2*x1 + 3*x2
  3. Loads the CSV into PyTorch tensors
  4. Defines a SimpleModel with a single nn.Linear(2, 1) layer
  5. Trains for 3000 epochs using SGD optimizer and MSE loss
  6. Saves the trained weights to py_torch_model.pth
  7. Loads the checkpoint and tests predictions on new inputs
Key components

Model architecture:

class SimpleModel(nn.Module):
    def __init__(self):
        super(SimpleModel, self).__init__()
        self.layer = nn.Linear(2, 1)
    def forward(self, x):
        return self.layer(x)

Training loop:

for epoch in range(num_epochs):
    y_pred = model(x_train)
    loss = loss_fn(y_pred, y_train)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

What you learn

  • How to structure a PyTorch model with nn.Module
  • How the forward pass, loss computation, and backward pass work
  • How to save and load model state dicts
  • The difference between training mode and evaluation mode

Limitations

This model can only fit linear relationships. The learned weights should converge to approximately w1≈2, w2≈3, matching the synthetic formula. This file does not export to ONNX or C/C++—it's purely for training demonstration.

Tip: Modify the synthetic data (e.g., output = 2*x1**2 + 3*x2) to see how the linear model fails to fit nonlinear functions. This motivates the hidden layers in File 2.

File 2: 2pytorch_non_linear.py — Full Python Pipeline

A complete self-contained workflow that trains a nonlinear model and deploys it to Raspberry Pi via ONNX Runtime. This is the Python deployment path.

Architecture

A 3-layer feedforward network with ReLU activations:

class NonlinearModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(2, 32)
        self.fc2 = nn.Linear(32, 32)
        self.fc3 = nn.Linear(32, 1)
    def forward(self, x):
        x = torch.relu(self.fc1(x))
        x = torch.relu(self.fc2(x))
        return self.fc3(x)

Layers: 2 inputs → 32 hidden → 32 hidden → 1 output. The two ReLU activations allow the model to fit any nonlinear function (universal approximation).

Workflow

Load and normalize data
Reads simple_nonlinear.csv, converts to PyTorch tensors, computes input statistics (mean/std).
Train the model
Uses Adam optimizer, trains for 1000 epochs on the nonlinear data. Prints loss every 100 epochs.
Save normalization stats
Stores mean and std to norm_stats.npz. Critical for inference—inputs must be normalized with the training stats.
Export to ONNX
Calls torch.onnx.export() to produce nonlinear_model.onnx. Sets model.eval() first to disable training-specific behavior.
Verify ONNX matches PyTorch
Runs inference on both and checks predictions match. If they differ, the export failed.
Generate Pi deployment script
Writes ml_onnx_minimal_for_pi.py—a minimal Python script that runs ONNX inference on the Pi.
Deploy via SSH
Uses sshpass to copy files to pi@raspi.local:~/. Requires sshpass installed and Pi SSH accessible.

History feedback loop

The file includes an example of feeding model predictions back as inputs:

history = deque(maxlen=10)
x1, x2 = 5.0, 5.0
for step in range(20):
    result = sess.run(None, {'input': x_norm})
    pred = result[0][0][0]
    history.append(pred)
    x1 = pred
    x2 = pred + step

This demonstrates temporal dynamics—useful for signal reconstruction, where the model's output becomes the next input.

File 3: 3train_export_deploy_cpp.py — Complete C/C++ Pipeline

The most complete file. Trains a nonlinear model and exports to native C and C++ inference code. Automatically deploys to Pi, compiles, and tests. This is the C/C++ deployment path.

9-step pipeline

Load data and train model
Same nonlinear architecture as File 2. Reads simple_nonlinear.csv, trains with Adam optimizer for 1000 epochs.
Save normalization stats
Saves mean and std to norm_stats.npz. Same as File 2.
Export to ONNX (for verification)
Creates ONNX to verify C/C++ results match PyTorch. This step is optional but recommended.
Extract weights to C header
Generates model_weights.h. All weight matrices (W1, W2, W3) and biases (B1, B2, B3) are static float arrays. Also includes normalization constants (MEAN, STD).
Generate C++ inference file
Creates inference.cpp. Implements linear_relu() and linear() functions for matrix-vector multiplication with activation functions. The predict() function normalizes inputs, runs through three layers, and returns output.
Generate C inference file
Creates inference.c. Identical logic to C++ but in plain C (no classes, just functions). Uses -lm flag for math library.
Test locally
Compiles C++ with g++ -O2 and runs locally to verify it works before deploying to Pi.
Deploy files to Pi
Uses sshpass to SCP all files (headers, source, stats) to pi@raspi.local:~/.
Compile and test on Pi
Generates a bash script, copies it to Pi, and executes it via SSH. Compiles both C and C++ versions and runs them. Prints predictions on the Pi itself—no data returned, just success/fail status.

Generated C header: model_weights.h

Example structure (truncated for brevity):

// Auto-generated model weights
#pragma once

static const float W1[2048] = { 0.1234f, -0.5678f, ... };
static const float B1[32] = { 0.0012f, -0.0034f, ... };

static const float W2[1024] = { ... };
static const float B2[32] = { ... };

static const float W3[32] = { ... };
static const float B3[1] = { 0.4567f };

static const float MEAN[2] = { 4.5f, 5.2f };
static const float STD[2] = { 2.3f, 1.8f };

All weights are compile-time constants—they are baked into the binary at compile time, with zero runtime overhead.

Inference core: linear_relu() and linear()

void linear_relu(const float* W, const float* B, const float* in,
                 float* out, int M, int N) {
    for (int j = 0; j < M; j++) {
        float v = B[j];
        for (int i = 0; i < N; i++)
            v += W[j*N + i] * in[i];
        out[j] = (v > 0.0f) ? v : 0.0f;  // ReLU
    }
}

float predict(float x1, float x2) {
    float x[2] = {
        (x1 - MEAN[0]) / STD[0],
        (x2 - MEAN[1]) / STD[1]
    };
    
    float h1[32], h2[32], out[1];
    linear_relu(W1, B1, x, h1, 32, 2);
    linear_relu(W2, B2, h1, h2, 32, 32);
    linear(W3, B3, h2, out, 1, 32);
    
    return out[0];
}

Performance: A single prediction takes ~1–2 microseconds on a Pi Zero (for this 2→32→32→1 model). No framework overhead.

Deployment Guide

Path A: Python ONNX (File 2)

When to use: You need flexibility, easier debugging, or your target has Python available. The Pi, most Linux boards, and some microcontroller frameworks support Python.

Prerequisites

  • Raspberry Pi (or other SBC) with DietPi, Raspberry Pi OS, or equivalent
  • SSH access: ssh pi@raspi.local
  • sshpass installed on development machine (for auto-deployment)
  • Python 3.8+ on Pi
  • pip install onnxruntime numpy pandas on Pi

Deployment steps (automated in File 2)

  1. Train model: Run File 2 on ai.local. Outputs: nonlinear_model.onnx, norm_stats.npz, ml_onnx_minimal_for_pi.py.
  2. Copy to Pi: 
    sshpass -p pi scp nonlinear_model.onnx pi@raspi.local:~/
sshpass -p pi scp norm_stats.npz pi@raspi.local:~/
sshpass -p pi scp ml_onnx_minimal_for_pi.py pi@raspi.local:~/
  3. Run inference on Pi: 
    ssh pi@raspi.local
cd ~
python ml_onnx_minimal_for_pi.py
Tip: If onnxruntime is slow to install via pip, download precompiled ARM wheels from onnxruntime releases.

Inference code on Pi (minimal)

import onnxruntime as ort
import numpy as np

sess = ort.InferenceSession('nonlinear_model.onnx')
stats = np.load('norm_stats.npz')

x_raw = np.array([[5.0, 5.0]], dtype=np.float32)
x_norm = (x_raw - stats['mean']) / stats['std']

result = sess.run(None, {'input': x_norm})
print(f"Prediction: {result[0][0][0]:.4f}")

Path B: Native C/C++ (File 3)

When to use: You need minimal footprint, zero-framework deployment, fastest inference, or your target is a microcontroller without Python support (ESP32, ARM Cortex-M).

Prerequisites

  • Raspberry Pi with standard C/C++ build tools
  • On Pi: sudo apt-get install build-essential
  • sshpass on development machine
  • No Python or external libraries required on target

Deployment steps (automated in File 3)

  1. Train model: Run File 3 on ai.local. Outputs all files including model_weights.h, inference.cpp, inference.c.
  2. Copy to Pi: 
    sshpass -p pi scp model_weights.h pi@raspi.local:~/
sshpass -p pi scp inference.cpp pi@raspi.local:~/
sshpass -p pi scp inference.c pi@raspi.local:~/
  3. Compile on Pi: 
    ssh pi@raspi.local
g++ -O2 -o inference_cpp inference.cpp
gcc -O2 -o inference_c inference.c -lm

./inference_cpp
./inference_c

Using with ESP32 or other MCU

The C code is platform-agnostic. To embed in an ESP32 or STM32:

  1. Copy model_weights.h and inference.c to your MCU project
  2. Call predict(x1, x2) from your MCU firmware
  3. Compile with your MCU's toolchain (e.g., arm-none-eabi-gcc for ARM)
// In your ESP32 sketch or bare-metal code:
#include "model_weights.h"
#include "inference.c"

float result = predict(5.0f, 5.0f);
Serial.println(result);
Tip: For embedded systems with limited RAM, the static weight arrays are stored in Flash (program memory), not RAM. No dynamic allocation needed.

Comparison: Deployment complexity

Path A (Python): More dependencies, slower install, slightly higher latency, easier to modify and debug post-deployment.

Path B (C/C++): Compile once, no dependencies at runtime, minimal binary, microsecond latency, harder to modify on-device.
